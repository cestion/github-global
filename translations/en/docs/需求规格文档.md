## 1. Project Overview

### 1.1 Project Name

**GitHub Global** (github-global)

### 1.2 Project Positioning

A one-stop GitHub repository multi-language translation SaaS platform that helps open source project authors automatically translate documentation into multiple languages and expand their international influence.

### 1.3 Target Users

- Open source project maintainers
- Technical blog/tutorial authors
- Developers looking to internationalize their projects
- Chinese projects going global

### 1.4 Core Value Proposition

> **"Zero configuration, one-click translation, take your GitHub project global"**

Compared to existing solutions (such as Azure/co-op-translator), this project's unique value:

- ✅ **Ready to use** - No need to configure GitHub Actions or local environment
- ✅ **SaaS service** - Provides ready-made web service for online operation
- ✅ **Multi-model support** - Unified access to various AI models through OpenRouter
- ✅ **Smart sync** - Automatically detect GitHub commit changes for incremental translation
- ✅ **Visual configuration** - Select translation scope through UI, no need to write config files manually

#### 3.2.2 Translation Scope Configuration

**Visual Configuration Interface**:

- Display repository file tree structure
- Checkbox to select directories/files to translate
- Support select all/invert selection
- Automatically identify Markdown files

**Config File Sync**:

- Visual selection results automatically sync to `.github-global-ignore` file
- After modifying config file, UI automatically updates

**`.github-global-ignore` File Format**:

```gitignore
# Ignore node_modules
node_modules/

# Ignore specific files
CHANGELOG.md
CONTRIBUTING.md

# Ignore specific directories
docs/internal/
.vuepress/
```

#### 3.2.3 Translation Storage Structure

Translated files are stored in `translations/` directory, organized by language:

```
repository/
├── README.md                    # Base language (Chinese)
├── docs/
│   └── guide.md
├── translations/
│   ├── en/                      # English translation
│   │   ├── README.md
│   │   └── docs/
│   │       └── guide.md
│   ├── ja/                      # Japanese translation
│   │   ├── README.md
│   │   └── docs/
│   │       └── guide.md
│   └── ...
└── .github-global-ignore        # Ignore config file
```

#### 3.2.4 Multi-language Link Generation

After AI analyzes README file structure, insert multi-language switching links at appropriate positions:

**Generated Format Example**:

```markdown
## 🌐 多语言版本 / Translations

[English](./translations/en/README.md) | [日本語](./translations/ja/README.md) | [한국어](./translations/ko/README.md)

---
```

**Insertion Position Strategy**:

1. If there is an existing language switching area, update that area
2. If there is an introduction area after the project title, insert after the introduction
3. If there is a table of contents (TOC), insert before the TOC
4. Fallback: Insert at the beginning of the file

## 8. Risks and Mitigation

| Risk | Impact | Mitigation Strategy |
| ------------------- | ---------------- | ---------------------------------- |
| OpenRouter API rate limit | Slow translation speed | Support user-provided API Key; implement request queue |
| GitHub API rate limit | Cannot fetch repository info | Cache API responses; optimize request frequency |
