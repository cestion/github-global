## 前提条件

開始する前に、以下が完了していることを確認してください：

1. ✅ [人工設定ドキュメント](./人工配置文档.md) のすべての設定手順が完了していること
2. ✅ Node.js 20+ および npm 10+ がインストールされていること
3. ✅ MySQL 8.0+ がインストールされていること
4. ✅ `.env` ファイルが設定されていること

## 方法1: ローカル開発起動

### 1. 依存関係のインストール

```bash
npm install
```

### 2. Prisma Client の生成

```bash
npm run db:generate
```

### 3. データベースの初期化

#### 方法A: Prisma Migrate を使用（推奨）

```bash
npm run db:migrate
```

これにより、データベースマイグレーションファイルが作成され、データベースに適用されます。

#### 方法B: Schema を直接プッシュ

```bash
npm run db:push
```

これにより、Prisma Schema がデータベースに直接同期されます（開発環境に最適）。

### 4. 開発サーバーの起動

```bash
npm run dev
```

### 5. アプリケーションへのアクセス

ブラウザでアクセス: http://localhost:3000

---

## 方法2: Docker デプロイ

### 1. 環境変数の設定

`.env` ファイルが正しく設定されていることを確認してください。

### 2. Docker Compose の起動

```bash
docker-compose up -d
```

これにより、2つのコンテナが起動します：
- `app`: Next.js アプリケーション
- `db`: MySQL データベース

### 3. データベースマイグレーションの実行

```bash
docker-compose exec app npx prisma migrate deploy
```

### 4. ログの確認

```bash
docker-compose logs -f app
```

### 5. アプリケーションへのアクセス

ブラウザでアクセス: http://localhost:3000

### 6. サービスの停止

```bash
docker-compose down
```

### 7. データのクリーンアップ（オプション）

```bash
docker-compose down -v  # データボリュームの削除
```

## 使用流程

### 1. システムログイン

1. http://localhost:3000 にアクセス
2. 「GitHubでログイン」をクリック
3. GitHub App を承認

### 2. リポジトリのインポート

API を使用してリポジトリをインポート：

```bash
curl -X POST http://localhost:3000/api/repos \
  -H "Content-Type: application/json" \
  -d '{
    "repoUrl": "https://github.com/username/repo-name"
  }'
```

### 3. 翻訳の設定

リポジトリ設定を更新：

```bash
curl -X PUT http://localhost:3000/api/repos/{repo_id}/config \
  -H "Content-Type: application/json" \
  -d '{
    "baseLanguage": "zh-CN",
    "targetLanguages": ["en", "ja", "ko"]
  }'
```

### 4. 翻訳タスクの作成

```bash
curl -X POST http://localhost:3000/api/translations \
  -H "Content-Type: application/json" \
  -d '{
    "repositoryId": "{repo_id}",
    "targetLanguages": ["en", "ja"],
    "type": "FULL"
  }'
```

### 5. 翻訳進捗の確認

SSE を使用してリアルタイムで進捗を取得：

```javascript
const eventSource = new EventSource('/api/translations/{task_id}/progress');

eventSource.onmessage = (event) => {
  const data = JSON.parse(event.data);
  console.log('進捗:', data.progress);
};
```

### 6. Pull Request の確認

翻訳が完了すると、自動的に Pull Request が作成され、GitHub リポジトリで表示・マージできます。

## トラブルシューティング

### 問題1: ポートが使用中

**エラー**: `Error: listen EADDRINUSE: address already in use :::3000`

**解決策**:

```bash
# Windows
netstat -ano | findstr :3000
taskkill /PID <PID> /F

# macOS/Linux
lsof -ti:3000 | xargs kill -9
```

### 問題2: データベース接続失敗

**エラー**: `Can't reach database server at localhost:3306`

**解決策**:

1. MySQL が起動しているか確認
2. `.env` の `DATABASE_URL` 設定を確認
3. データベース接続をテスト：

```bash
mysql -h localhost -u github_global -p
```

### 問題3: Prisma Client が生成されていない

**エラー**: `Cannot find module '@prisma/client'`

**解決策**:

```bash
npm run db:generate
```

### 問題4: GitHub App 認証失敗

**エラー**: `Error: Invalid GitHub App credentials`

**解決策**:

1. `.env` の GitHub App 設定を確認
2. 秘密鍵の形式が正しいことを確認
3. App ID と Client ID が一致しているか確認

### 問題5: OpenRouter API 呼び出し失敗

**エラー**: `401 Unauthorized` または `429 Rate Limit`

**解決策**:

1. API Key が正しいか確認
2. OpenRouter アカウントの残高を確認
3. API レート制限を超えていないか確認

## パフォーマンス最適化建议

### 1. データベースの最適化

- 古い翻訳タスクレコードを定期的にクリーンアップ
- よく使うクエリにインデックスを追加
- 接続プールを使用

### 2. 翻訳キューの最適化

- 同時実行数を調整（デフォルトは3）
- 本番環境ではローカルキューの代わりに Redis を使用

### 3. API キャッシュ

- 言語リストとモデルリストをキャッシュ
- リポジトリファイルツリーを短時間キャッシュ

## 本番環境デプロイ建议

### 1. 環境変数

- 本番環境のドメインで `NEXTAUTH_URL` を更新
- 強力なパスワードとキーを使用
- 機密情報をコードにハードコードしない

### 2. データベース

- クラウドデータベースサービスを使用（AWS RDS、阿里雲 RDS など）
- データベースバックアップを設定
- SSL 接続を有効化

### 3. リバースプロキシ

Nginx または Caddy をリバースプロキシとして使用：

```nginx
server {
    listen 80;
    server_name your-domain.com;

    location / {
        proxy_pass http://localhost:3000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_cache_bypass $http_upgrade;
    }
}
```

### 4. HTTPS

Let's Encrypt を使用して SSL 証明書を設定：

```bash
certbot --nginx -d your-domain.com
```

### 5. モニタリングとログ

- ログ収集を設定（Winston、Pino など）
- エラー監視を設定（Sentry など）
- パフォーマンス監視を設定（New Relic など）
