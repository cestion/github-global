# GitHub Global - 保姆級ローカル実行ガイド

このドキュメントでは、ゼロからローカルで GitHub Global プロジェクトを実行する方法をステップバイステップで解説します。手順に従えば、詳細を漏らすことなく実行できます。

## 前提条件

以下のソフトウェアがコンピュータにインストールされていることを確認してください：

| ソフトウェア | 最低バージョン | 確認コマンド | インストール先 |
|---|---|---|---|
| Node.js | 20.0.0 | `node -v` | [nodejs.org](https://nodejs.org/en) |
| npm | 10.0.0 | `npm -v` | Node.js に含まれる |
| MySQL | 8.0 | `mysql --version` | [dev.mysql.com](https://dev.mysql.com/downloads/) |
| Git | 任意バージョン | `git --version` | [git-scm.com](https://git-scm.com/) |

> **Windows ユーザーへの注意**：以下のコマンドはすべて **Git Bash** で実行することをお勧めします。コマンドの互換性問題を避けるためです。

## ステップ1：プロジェクトをクローン

```bash
git clone https://github.com/liyupi/github-global.git
cd github-global
```

## ステップ2：依存関係をインストール

```bash
npm install
```

インストールが完了すると、`node_modules` フォルダが作成されます。インストールに失敗した場合は、以下を試してください：

```bash
# キャッシュをクリアして再試行
rm -rf node_modules package-lock.json
npm install
```

## ステップ3：MySQL データベースを作成

### 3.1 MySQL サービスを起動

- **macOS**（Homebrew インストール）：`brew services start mysql`
- **Windows**：「サービス」で MySQL を起動するか、MySQL インストーラーに含まれる起動方法を使用
- **Linux**：`sudo systemctl start mysql`

### 3.2 データベースを作成

任意の MySQL クライアント（コマンドライン / Navicat / IDEA データベースプラグインなど）でローカルの MySQL に接続し、以下を実行：

```sql
CREATE DATABASE github_global CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```

> MySQL のユーザー名やパスワードを変更した場合は、覚えておいてください。環境変数の設定時に必要です。

## ステップ4：GitHub App を作成

これはプロジェクトの**重要な前提設定**です。GitHub App を作成しないとログインして使用できません。

### 4.1 作成ページにアクセス

GitHub にログインし、[https://github.com/settings/apps/new](https://github.com/settings/apps/new) にアクセスします。

### 4.2 基本情報を入力

| 項目 | 入力内容 |
|---|---|
| **GitHub App name** | 好きな名前（例：`my-github-global`）を付けてください。グローバルで一意である必要があります |
| **Homepage URL** | `http://localhost:3123` |
| **Callback URL** | `http://localhost:3123/api/auth/callback/github` |
| **Setup URL**（任意） | 空のままにしてください |
| **Webhook** | **チェックを外す** Active（ローカル開発では現時点では不要） |

> ポートは **3123** であることに注意してください。デフォルトの 3000 ではありません。

### 4.3 権限を設定

**Permissions** セクションを展開し、以下の権限を設定します：

**Repository permissions（リポジトリ権限）：**

| 権限 | レベル | 用途 |
|---|---|---|
| **Contents** | Read & Write | リポジトリファイルの読み取り、翻訳ファイルの書き込み |
| **Metadata** | Read-only | リポジトリの基本情報の読み取り |
| **Pull requests** | Read & Write | 翻訳完了 PR の作成 |
| **Webhooks** | Read & Write | 自動翻訳機能に必要（暫定で設定不要） |

**Account permissions（アカウント権限）：**

| 権限 | レベル | 用途 |
|---|---|---|
| **Email addresses** | Read-only | ユーザーメールアドレスの取得 |

### 4.4 インストール範囲を設定

ページ下部の **Where can this GitHub App be installed?** で以下を選択：

- **Any account** — すべてのユーザーがインストール可能

### 4.5 作成してキーを取得

**Create GitHub App** ボタンをクリックして作成成功后：

1. **App ID を記録**：ページ最上部の `App ID`
2. **Client ID を記録**：ページの `Client ID`（形式は `Iv23li...`）
3. **Client Secret を生成**：`Generate a new client secret` をクリックし、**今すぐコピーして保存**（一度だけ表示されます）
4. **Private Key を生成**：`Generate a private key` をクリックし、ブラウザが `.pem` ファイルをダウンロードします
5. **App Slug を記録**：GitHub App 名の小文字ハイフン版（例：`my-github-global`）です。App ページの URL で見ることができます：`https://github.com/settings/apps/my-github-global`

### 4.6 秘密鍵ファイルを配置

ダウンロードした `.pem` 秘密鍵ファイルの名前を `private-key.pem` に変更し、プロジェクトのルートディレクトリに置きます：

```
github-global/
├── private-key.pem    ← ここに配置
├── package.json
├── ...
```

> このファイルは `.gitignore` に含まれているため、Git にコミットされません。

## ステップ5：OpenRouter API Key を取得

プロジェクトは [OpenRouter](https://openrouter.ai/) を使用して様々な AI 大規模モデルを統一的に呼び出し翻訳を行います。

1. [https://openrouter.ai/](https://openrouter.ai/) にアクセスし、新規登録してログイン
2. [API Keys ページ](https://openrouter.ai/keys) に移動し、**Create Key** をクリック
3. 生成された API Key をコピー（形式は `sk-or-v1-xxxx...`）

> 新規登録ユーザーは通常無料枠があり、ローカルテストには十分です。

## ステップ6：環境変数を設定

### 6.1 設定ファイルを作成

プロジェクトには `.env` と `.env.local` の2つの環境変数ファイルが必要です：

```bash
cp .env.example .env
cp .env.example .env.local
```

### 6.2 設定を記入

エディタで `.env` と `.env.local` を開き（2つのファイルの内容を一貫させる）、以下の説明に従って記入します：

```bash
# ===== データベース =====
# 形式：mysql://ユーザー名:パスワード@アドレス:ポート/データベース名
# MySQL root パスワードが 123456 の場合：
DATABASE_URL=mysql://root:123456@localhost:3306/github_global

# ===== NextAuth 認証 =====
# ローカル開発アドレス（ポートは 3123 に注意）
NEXTAUTH_URL=http://localhost:3123
# 32文字以上のランダムな文字列。Session の暗号化に使用
AUTH_SECRET=this-is-a-random-secret-string-at-least-32-chars

# ===== GitHub App 設定 =====
# ステップ4で取得した情報を入力
GITHUB_APP_ID=あなたのAppID
GITHUB_APP_CLIENT_ID=あなたのClientID
GITHUB_APP_CLIENT_SECRET=あなたのClientSecret
GITHUB_APP_PRIVATE_KEY_PATH=./private-key.pem
GITHUB_APP_SLUG=あなたのapp名slug

# ===== Webhook（ローカル開発では空で可） =====
GITHUB_WEBHOOK_SECRET=

# ===== OpenRouter =====
PLATFORM_OPENROUTER_API_KEY=sk-or-v1-あなたのkey
```

### 6.3 2つのファイルの関係

| ファイル | 読み取り元 | 説明 |
|---|---|---|
| `.env` | Prisma / バックエンドコード | データベース接続、GitHub App 設定 |
| `.env.local` | Next.js / NextAuth | 認証関連設定（NextAuth はこのファイルのみ読み取り） |

> 設定漏らしを避けるため、**2つのファイルの内容を完全に一致させることを推奨**します。

## よくある問題のトラブルシューティング

### Q1：npm install が失敗する

```bash
# キャッシュをクリアして再試行
rm -rf node_modules package-lock.json
npm install

# ネットワーク問題がある場合は、国内ミラーが使用可能
npm install --registry=https://registry.npmmirror.com
```

### Q2：データベース接続に失敗する

以下を順番に確認：
1. MySQL サービスが起動しているか
2. `.env` ファイルの `DATABASE_URL` のユーザー名とパスワードが正しいか
3. データベース `github_global` が作成されているか
4. ファイアウォールが 3306 ポートをブロックしていないか

### Q3：GitHub ログイン後にエラー 500 が発生する

- `.env.local` ファイルが存在し正しく設定されているか確認（NextAuth は `.env.local` のみ読み取り）
- `GITHUB_APP_CLIENT_ID` と `GITHUB_APP_CLIENT_SECRET` が正しく入力されているか確認
- GitHub App の Callback URL が `http://localhost:3123/api/auth/callback/github` に設定されているか確認

### Q4：Private Key の読み取りに失敗する

- `private-key.pem` ファイルがプロジェクトのルートディレクトリにあるか確認
- ファイルの内容が完全か確認（`-----BEGIN RSA PRIVATE KEY-----` で始まり、`-----END RSA PRIVATE KEY-----` で終わる）
- `.env` の `GITHUB_APP_PRIVATE_KEY_PATH=./private-key.pem` が正しいか確認

### Q5：翻訳タスクが失敗する

- ターミナルコンソールのエラーログを確認し、具体的なエラー原因を特定
- **401 Unauthorized**：OpenRouter API Key が無効または残高不足
- **403 Forbidden**：選択した AI モデルが現在の地域で利用不可。別のモデルを試す
- **422 sha wasn't supplied**：ターゲットファイルは既に存在するがコードが SHA を取得していない。通常は翻訳を再実行すれば解決

### Q6：ページのスタイルが異常 / ホワイトスクリーン

```bash
# Next.js キャッシュをクリアして再起動
rm -rf .next
npm run dev
```

### Q7：ポート 3123 が使用中

```bash
# macOS / Linux で使用プロセスを確認
lsof -i :3123

# Windows で使用プロセスを確認
netstat -ano | findstr :3123

# プロセスを終了して再起動
```

### Q8：ログイン後にリポジトリを操作できない（権限不足）

GitHub App がまだアカウントにインストールされていない可能性があります：
1. GitHub の **Settings → Applications → GitHub Apps** に移動
2. 作成した App を見つけ、**Configure** をクリック
3. 承認するリポジトリを選択して保存

それでも問題が解決しない場合は、まずアンインストールしてから再インストールしてみてください。

## 上級編：自動増分翻訳を有効にする

自動増分翻訳は GitHub がローカルサービスにアクセスできる必要があるため、**内網穿透**が必要です。

### 1. Ngrok をインストール

[ngrok.com](https://ngrok.com/) からダウンロードしてインストールし、API キーをバインドします：

```bash
ngrok config add-authtoken あなたのAuthToken
```

### 2. 内網穿透を起動

```bash
ngrok http 3123
```

次のようなパブリックアドレスが得られます：`https://xxxx-xxx.ngrok-free.app`。

### 3. 設定を更新

`.env` と `.env.local` の `NEXTAUTH_URL` をパブリックアドレスに変更します：

```bash
NEXTAUTH_URL=https://xxxx-xxx.ngrok-free.app
```

同時に GitHub App 設定ページで以下を更新：
- **Callback URL** → `https://xxxx-xxx.ngrok-free.app/api/auth/callback/github`
- **Webhook Active** にチェックを入れ、**Webhook URL** → `https://xxxx-xxx.ngrok-free.app/api/webhooks/github` を記入
- **Webhook Secret** を記入（`.env` の `GITHUB_WEBHOOK_SECRET` と同じにする）

### 4. Webhook 権限を設定

GitHub App 設定ページで：
- **Repository permissions → Webhooks**：`Read & Write` に設定
- **Subscribe to events**：`Push` にチェックを入れる

保存後、GitHub App を再インストールし、プロジェクトの翻訳設定ページで「自動翻訳」スイッチを有効にします。
